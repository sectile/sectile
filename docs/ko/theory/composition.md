# 조합 원리

컴포넌트는 구조, 독립된 상태, 명시적인 규칙과 실행 환경 명령을 조합합니다. 하나의 사실은 한 모델만 소유하므로 규칙을 바꿨다고 구조가 조용히 변하거나 상태의 주인이 둘이 되는 일이 없습니다.

## 조합 방법

| 방법 | 뜻 |
| --- | --- |
| 곱 | 서로 독립된 구조나 상태를 함께 둡니다. |
| 합 | 동시에 성립할 수 없는 방식 가운데 하나를 고릅니다. |
| 제한 | 법칙을 더해 허용할 값을 좁힙니다. |
| 투영 | 기준 상태에서 관찰 가능한 화면용 결과를 계산합니다. |
| 매개변수화 | 동작 규칙이나 기능을 명시적으로 전달합니다. |
| 트랜잭션 | 하위 상태 변화를 계산한 뒤 한꺼번에 반영합니다. |
| 변경 차수 | 오래된 입력을 순서가 있는 상태 번호로 거부합니다. |

## 목록 상자 예시

```text
순서
× 현재 위치
× 선택
× 사용 가능 여부
× 이동에 따른 선택 규칙
× 포커스 명령
```

순서는 항목의 배치를 소유하고, 현재 위치는 지금 탐색 중인 항목을 소유합니다. 선택은 고른 식별자를 소유합니다. 현재 위치를 옮길 때 선택도 바꿀지는 규칙이 결정하고, 실제 포커스 이동은 실행 환경이 수행합니다.

## 콤보박스 예시

```text
텍스트
× 팝업 상태
× (순서 | 격자 | 계층)
× 현재 위치
× 선택
× 검색과 확정 규칙
× 포커스와 확정 명령
```

한글 조합 입력은 명시적으로 확정하거나 취소하기 전까지 텍스트의 조합 상태로 남습니다. 후보를 고르는 동작이 조합 중인 글자를 이미 확정된 검색어로 잘못 해석하지 않습니다.

## 계층 격자 예시

```text
계층
× 격자 좌표
× 펼침
× 현재 위치
× 선택
× 편집 상태
```

조합 모델은 행의 식별자와 칸 좌표 사이의 연결만 소유합니다. 계층과 격자는 하나의 모호한 구조로 합쳐지지 않고 각자의 법칙을 그대로 유지합니다.
