# 이론

Sectile은 상호작용을 작은 의미 모델의 조합으로 정의합니다. 화면 출력, 프레임워크 수명 주기와 시각 스타일은 이 모델 밖에 둡니다. 덕분에 브라우저, 터미널, 프레임워크가 달라도 동작의 뜻은 바뀌지 않습니다.

## 명세의 구성

모든 모델은 같은 관찰 규칙으로 설명합니다.

```text
이론 = 값의 종류 + 유효한 값 + 연산 + 관찰 결과 + 법칙 + 오류 + 비용
```

- **유효한 값**은 어떤 상태를 만들 수 있는지 정합니다.
- **연산**은 값을 만들거나 바꿉니다.
- **관찰 결과**는 사용자가 확인할 수 있는 공개 결과입니다.
- **법칙**은 모든 유효한 상태와 변화에서 항상 성립합니다.
- **오류**는 잘못된 입력과 단순히 값이 없는 경우를 구분합니다.
- **비용**은 시간과 메모리 사용 한도를 계약에 포함합니다.

같은 공개 입력을 주었을 때 결과, 오류, 상태와 명령의 순서가 같다면 두 구현은 같은 동작으로 봅니다.

## 공통 어휘

Sectile은 [순서, 범위, 격자, 계층](/ko/theory/structures)을 기본 구조로 삼고 [현재 위치, 선택, 펼침, 텍스트](/ko/theory/state-and-text)을 독립된 상태로 둡니다. 항목을 건너뛸지, 끝에서 멈출지 같은 선택은 숨겨진 부수 효과가 아니라 명시적인 규칙으로 전달합니다.

컴포넌트는 이 요소를 [결정적인 상태 전이](/ko/theory/transitions)로 조합합니다. 브라우저와 터미널 패키지는 그 결과를 각 환경의 포커스, 화면 표시와 입력 방식으로 연결합니다.

## 조합이 기본 단위다

목록 상자, 달력, 콤보박스와 계층 격자는 서로 무관한 상태 기계가 아닙니다. 같은 구조와 상태 모델을 목적에 맞게 조합한 결과입니다. [조합 원리](/ko/theory/composition)에서 관계를 한눈에 볼 수 있습니다.
