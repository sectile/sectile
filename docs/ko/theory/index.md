# 코어 이론

`@sectile/core`는 목록 상자, 달력, 슬라이더처럼 사용자의 입력에 반응하는 동작을 상태 전이로 정의합니다. 현재 상태와 사용자가 일으킨 사건을 받으면 다음 상태와 실행할 명령 목록을 돌려줍니다. 같은 입력에서는 언제나 같은 결과가 나오므로 브라우저, 터미널, Vue에서 동작을 똑같이 검증할 수 있습니다.

화면 요소와 프레임워크 연결은 DOM·Terminal·Vue 패키지가 담당합니다. 달력 날짜 계산은 Temporal, 큰 목록의 배치는 Virtual이 맡습니다. Core는 이 패키지들이 함께 쓰는 상호작용 규칙을 제공합니다.

## 명세의 구성

각 모델의 문서는 값, 연산, 결과 순서로 읽습니다. 여기에 법칙과 오류, 계산 비용을 함께 적어 두면 구현이 달라져도 같은 동작인지 판단할 수 있습니다.

<TheoryContractDiagram />

유효한 값은 상태로 만들 수 있는 범위를 정합니다. 연산은 사건을 받아 값을 바꾸는 절차이고, 관찰 결과는 밖에서 확인할 상태와 명령, 조회값입니다. 법칙은 모든 상태 전이가 지켜야 할 조건을 담습니다. 오류는 입력 형식 문제와 빈 조회 결과를 서로 다른 종류로 표시합니다. 비용에는 시간과 메모리의 최대 사용량이 들어갑니다.

이 기준을 모두 맞추면 내부 코드가 달라도 같은 동작으로 볼 수 있습니다.

## 공통 어휘

Sectile은 [순서, 범위, 격자, 계층](/ko/theory/structures)을 항목 관계의 기본형으로 씁니다. [현재 항목, 선택, 펼침, 텍스트](/ko/theory/state-and-text)는 각각 한 가지 사실만 저장합니다. 예를 들어 현재 항목이 바뀌어도 선택은 그대로 둘 수 있고, 선택을 현재 항목과 함께 옮길 수도 있습니다. 어떤 방식을 쓸지는 컴포넌트의 규칙이 정합니다.

컴포넌트는 이 재료를 [상태 전이](/ko/theory/transitions)로 조합합니다. 브라우저와 터미널 패키지는 결과에 담긴 포커스 이동, 스크롤, 알림 같은 명령을 각 환경의 기능으로 실행합니다.

날짜와 달력 규칙은 [`@sectile/temporal`](/ko/packages/temporal), 화면 영역과 동적 크기 측정은 [`@sectile/virtual`](/ko/packages/virtual) 문서에서 설명합니다.

## 조합이 기본 단위다

목록 상자는 순서에 현재 항목과 선택을 더합니다. 달력은 격자에 날짜 이동 규칙과 선택을 얹습니다. 콤보박스는 순서, 텍스트, 팝업 상태를 함께 씁니다. [조합 원리](/ko/theory/composition)에서 컴포넌트마다 어떤 재료를 묶는지 확인할 수 있습니다.
