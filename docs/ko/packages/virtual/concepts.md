# 가상화 동작 원리

가상화에 필요한 정보는 항목 순서와 크기, 배치 조건, 불러온 자료로 나누어 관리합니다. 각 영역이 안정적인 ID를 공유하므로 항목 추가·삭제·이동과 화면에 나온 뒤의 크기 변경에서도 스크롤 위치를 지킬 수 있습니다.

<VirtualConceptDiagram />

## 서로 다른 범위

- **화면 영역**: 사용자가 지금 보고 있는 사각형
- **그릴 범위**: 화면 주변에서 미리 그려 둘 영역
- **배치 결과**: 그릴 범위에 들어온 ID와 좌표
- **자료 범위**: 앱이 지금 불러온 자료

그릴 범위는 스크롤에 맞춰 바뀌고, 자료 범위는 서버에서 받은 결과에 맞춰 바뀝니다. `collectionWindowEventForLinearPlan()`은 현재 그릴 범위에 필요한 자료 범위를 계산해 두 상태를 연결합니다.

## 모든 배치 방식이 따르는 계약

모든 배치 방식은 화면의 위치와 크기, 미리 그려 둘 거리를 받습니다. `VirtualLayoutPlan`에는 목록 전체 크기와 그릴 범위, 항목별 좌표, 실제로 보이는지 여부, 측정 순번, 기준 ID가 담깁니다.

항목 크기를 재거나 목록을 바꾸면 새 배치 상태와 `scrollDelta`가 나옵니다. 브라우저 연결 코드는 DOM에서 측정한 크기를 Virtual에 전달하고, 계산 결과를 화면에 그린 뒤 필요한 만큼 스크롤을 옮깁니다. 입력 배열은 앱이 계속 소유합니다.

## 항목 크기의 근거

`ExtentIndex`는 항목마다 다음 셋 가운데 하나를 저장합니다.

| 종류 | 뜻 |
| --- | --- |
| `exact` | 측정을 마쳤거나 다른 근거로 확정된 크기 |
| `estimated` | 실제와 가까울 것으로 예상한 임시 크기 |
| `unknown` | 측정 전이라 명시적인 대체값을 쓰는 크기 |

대체값은 실제 크기에 가깝게 잡는 편이 좋습니다. 처음 보이는 스크롤 길이와 실제 크기를 잰 뒤 움직일 거리가 이 값에 따라 달라집니다.
