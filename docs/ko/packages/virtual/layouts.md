# 화면에 맞는 배치 고르기

배치 방식은 모두 같은 조회 결과를 돌려주지만, 좌표를 만드는 과정이 다릅니다. 화면 구조에 맞는 방식을 고르면 앱에서 관리할 값과 변경 작업이 줄어듭니다.

위 예시는 공개 API만 써서 네 가지 배치를 만들고 화면에 필요한 항목을 찾습니다.

| 방식 | 앱이 전달하는 값 | Sectile이 계산하는 값 | 알맞은 화면 |
| --- | --- | --- | --- |
| 선형 | ID, 순서, 각 항목의 예상값 또는 측정한 크기 | 한 방향 좌표, 전체 길이, 기준 항목 보정 | 목록, 피드, 메시지 기록 |
| 트랙 격자 | 행 높이, 열 너비, 영역의 행·열과 차지하는 칸 수 | 행·열 좌표와 각 영역의 사각형 | 표, 일정표, 계산표 |
| 벽돌형 | 카드 순서와 각 카드의 높이 | 카드가 들어갈 열과 세로 좌표 | 사진 모음, 상품 탐색, 자료 보관함 |
| 자유 좌표 | 각 항목의 x·y 좌표, 너비·높이, 그리기 순서 | 화면과 겹치는 항목과 조회 순서 | 도식, 지도 주석, 자유 배치 편집기 |

## 전용 배치가 맡는 추가 작업

자유 좌표 방식은 앱이 항목의 사각형을 이미 알고 있을 때 가장 단순합니다. 다이어그램 편집기는 사용자가 노드를 끌어 놓는 순간부터 각 노드의 x·y 좌표를 가지고 있으므로, Sectile은 넓은 캔버스에서 현재 화면과 겹치는 노드만 찾으면 됩니다.

목록은 상황이 다릅니다. 첫 번째 행의 높이가 8px 늘어나면 뒤에 있는 모든 행의 세로 위치가 함께 이동합니다. 목록 배치는 누적 크기 인덱스로 이 변화를 처리하고, 화면 위쪽에서 변화가 생기면 사용자가 읽던 행을 기준으로 스크롤 위치도 보정합니다. 자유 좌표 방식을 쓰면 앱이 이 계산을 직접 구현해 모든 사각형을 다시 전달해야 합니다.

격자는 행과 열을 따로 바꿀 수 있고, 벽돌형은 카드 높이에 따라 열 배치가 달라집니다. 각 방식은 구조에서 얻을 수 있는 규칙을 사용하므로 좌표를 전부 저장하는 것보다 적은 값으로 변경을 처리합니다.

## 트랙 격자

```ts
import { createExtentIndex } from '@sectile/virtual/extent-index'
import { createTrackGridLayout } from '@sectile/virtual/track-grid-layout'

const exact = (value: number) => ({ kind: 'exact' as const, value })
const grid = createTrackGridLayout(
  createExtentIndex([exact(32), exact(40), exact(40)]),
  createExtentIndex([exact(180), exact(120), exact(120)]),
  [{ id: 'title', row: 0, column: 0, columnSpan: 3 }],
  { rowGap: 1, columnGap: 1 },
)
```

저장 공간은 행 수와 열 수, 직접 지정한 영역 수에 비례합니다. 빈 칸은 조회 결과에 든 행·열 범위에서 화면 요소로 만들 수 있습니다. 행이나 열을 고정하려면 같은 상태를 서로 다른 화면 영역으로 조회합니다.

## 벽돌형

`shortest`는 가장 짧은 열부터 채워 전체 높이를 고르게 맞춥니다. 실제 크기를 재고 나면 뒤쪽 항목이 다른 열로 옮겨갈 수 있습니다. 항목이 처음 들어간 열에 계속 남아야 한다면 `round-robin`을 사용합니다. 열 수가 바뀌면 새 좌표와 함께 스크롤을 옮길 거리도 돌려줍니다.

## 자유 배치

자유 좌표 배치는 원하는 사각형 좌표를 받아 `zIndex`와 선언 순서에 맞춰 항목을 돌려줍니다. 앱이 좌표를 직접 정하는 화면에서는 사각형을 Sectile에 전달하고, 사용자가 항목을 움직일 때 바뀐 사각형만 갱신합니다.
