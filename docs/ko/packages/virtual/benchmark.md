# 가상화 벤치마크

10만 개 행을 일곱 개 라이브러리로 그렸습니다. 같은 높이의 단순한 행과 내용에 따라 높이가 달라지는 실제 UI를 각각 측정합니다. 초기 렌더와 스크롤 반응뿐 아니라 삽입·이동·삭제·높이 변경 뒤 화면이 안정되는 시간도 확인할 수 있습니다.

## 행 구성을 나눈 이유

같은 높이 실험은 라이브러리의 기본 비용을 비교합니다. 서로 다른 높이 실험은 제목, 본문, 태그, 펼친 상세 내용이 섞인 256가지 행을 사용합니다. 접힌 행만 해도 높이가 8단계로 나뉘며 실제 범위는 71–159px입니다. 행 순서는 고정된 난수 규칙으로 정해져 모든 라이브러리가 같은 데이터를 받습니다.

앱은 행별 높이 계산과 전달을 생략합니다. 각 라이브러리가 화면에 만든 DOM을 직접 재고 다음 배치를 갱신합니다. 러너가 따로 측정한 정답 높이는 판정에만 씁니다.

화면에 나타난 행부터 실제 높이가 확정됩니다. 이질적 높이 실험은 현재 화면의 행 높이, 순서, 겹침, 빈 영역, 스크롤 기준 위치를 엄격하게 판정하고 전체 높이 추정 오차는 별도 수치로 기록합니다.

## 높이 입력 조건

정확한 높이, 예상 높이, DOM 실측 조건을 각각 측정합니다. 고정 높이 전용 경로와 DOM 실측 경로의 비용을 분리해 비교할 수 있습니다.

- 고정 높이: 앱이 정확한 72px을 전달합니다. 같은 높이 실험에서만 사용합니다.
- 예상값 제공: 앱이 모든 행에 공통으로 쓸 72px을 전달합니다. 라이브러리는 화면에 나타난 행을 DOM에서 다시 잽니다.
- 높이 생략: 앱의 높이 입력을 생략합니다. Sectile은 viewport를 채울 초기 표본을 먼저 만들고 실제 DOM 높이를 잰 뒤, 그 측정값으로 나머지 전체 범위를 구성합니다.

높이 생략 조건은 높이 입력 없이 시작하는 API에서 실행합니다. 입력값이 필요한 라이브러리는 해당 조건에 필요한 값을 표시합니다.

높이 변경 실험에서는 선택한 행의 상세 내용을 펼칩니다. 문장이 추가되면서 생긴 높이 변화는 브라우저 DOM에서 읽습니다.

각 라이브러리가 요구하는 연결 방식은 그대로 따랐습니다. `react-virtualized`는 측정 캐시를 비우고 목록 배치를 다시 계산하라는 호출이 필요합니다. 나머지 비교 대상은 DOM 크기 변경을 자동으로 감지하는 API를 사용했습니다. 이런 앱 코드의 차이도 실행 시간에 포함됩니다.

## 목록 변경 실험

삽입·이동·삭제·높이 변경을 목록의 세 지점에서 실행합니다.

- 시작: 첫 번째 행
- 중간: 50,000번째 행을 화면 맨 위에 둔 상태
- 끝: 마지막 행이 보이도록 맨 아래까지 내린 상태

삽입과 삭제, 높이 변경은 해당 지점의 행 하나를 바꿉니다. 이동은 그 행과 바로 옆 행의 순서를 맞바꿉니다. 매번 10만 개의 원본 목록으로 되돌린 뒤 같은 실험을 50회 반복합니다.

시간은 목록 변경을 요청한 순간부터 DOM 순서와 행 높이, 화면을 채운 상태, 기준 행의 위치가 모두 맞는 첫 프레임까지 잽니다. 같은 높이 조건에서는 전체 스크롤 높이도 완료 판정에 포함합니다. 다섯 개의 독립 인스턴스에서 각각 10회 측정하며, 표본 사이에는 원본 목록과 화면 배치를 확인한 뒤 다음 변경을 시작합니다. 복원 검사를 통과한 인스턴스만 다음 표본에 사용합니다. 화면이 잠깐 어긋났다가 돌아오면 복구까지 걸린 시간과 오류 내용을 모두 남깁니다. 처음부터 맞았던 표본과 복구된 표본은 따로 집계합니다.

그래프의 안정화 시간은 올바른 화면에 도달한 표본 전체를 대상으로 계산합니다. 복구 시간은 중간 화면 오류를 거쳐 정상 화면으로 돌아온 표본만 따로 모은 값입니다. 현재 게재 결과는 2초 기준을 초과한 조건을 막대 대신 `복구 실패`로 표시합니다.

## 실패 판정

다음 현상을 프레임마다 검사합니다.

- 행 ID의 누락·중복·잘못된 순서
- 예상 높이와 다른 행
- 행 사이의 빈틈과 겹침
- 화면 위아래에 생긴 빈 영역
- 같은 높이 조건의 전체 스크롤 높이 오차
- 목록 변경 범위를 벗어난 기준 행의 위치 변화

한 프레임이라도 어긋나면 화면 오류로 기록합니다. 잘못된 배치가 300ms 이상, 8프레임 동안 같은 상태로 머물면 복구 실패로 판정합니다. 현재 게재 결과에서는 좌표가 계속 바뀌는 동안 최대 2초까지 검사를 이어갑니다. Sectile에서 발생한 오류는 원본 결과에서 `fatal`로 구분합니다.

## 초기 렌더와 스크롤

두 행 구성 모두 720 × 480px 화면에 10만 개 행을 넣습니다. 라이브러리마다 8행 분량의 여유 구간을 요청했습니다. 같은 높이 실험은 정확한 72px을 사용하고, 서로 다른 높이 실험의 공통 예상값도 72px로 맞춥니다.

라이브러리 순서를 바꿔 가며 세 번에서 다섯 번 실행합니다. 세 번째 실행부터 누적 중앙값과 p95가 안정되면 종료하고, 분포가 계속 바뀌면 다섯 번째 실행까지 이어갑니다. 초기 렌더 과정은 동기 설정이 끝난 시점, 첫 행이 나타난 시점, 처음 보이는 화면의 배치가 맞는 시점으로 나눠 기록합니다. 같은 높이 조건에서는 전체 스크롤 높이까지 맞아야 완료됩니다. 서로 다른 높이 조건의 전체 높이 오차는 별도 지표로 남깁니다.

매 실행에서 처음 다섯 번은 준비 과정으로 빼고, 이어지는 스크롤 20번을 기록합니다. 러너는 프레임 경계가 지난 뒤 `scrollTop`을 바꿉니다. 브라우저가 스크롤 이벤트를 전달하기 시작한 순간부터 바뀐 DOM의 좌표를 모두 읽은 순간까지를 스크롤 시간으로 잽니다. 이 좌표로 행 순서와 높이, 겹침, 화면의 빈틈을 확인합니다. 같은 높이 조건에서는 목표 행과 전체 스크롤 높이도 함께 검사합니다. 판정 코드의 실행 시간은 별도 probe로 기록합니다.

그래프에는 좌표 읽기 비용까지 포함한 상한을 씁니다. 원본 결과에는 좌표를 읽기 전의 하한, 좌표 읽기 비용, 검사 횟수, 라운드와 표본 번호를 기록했습니다. 중앙값 절대 편차와 라운드별 범위도 함께 남겨 느린 라운드의 분포를 드러냅니다.

초기 렌더와 스크롤 결과는 Sectile의 자동 높이 숫자 기본값을 제거한 뒤 2026년 8월 28일, Chrome 151, Apple Silicon, macOS에서 다시 측정했습니다. 지원되는 27개 행 구성·높이 입력 조건이 모두 완료됐습니다. 같은 높이의 높이 생략 조건은 전체 높이 오차 0%, 서로 다른 높이의 높이 생략 조건은 초기 전체 높이 오차 3.967%를 기록했습니다. 절대 시간은 기기와 브라우저 상태에 따라 달라집니다. 라이브러리 사이의 상대 차이와 정확도 결과를 함께 읽어야 합니다.

비교 대상은 [TanStack Virtual](https://www.npmjs.com/package/%40tanstack/react-virtual), [react-window](https://www.npmjs.com/package/react-window), [React Virtuoso](https://www.npmjs.com/package/react-virtuoso), [react-virtualized](https://www.npmjs.com/package/react-virtualized), [Virtua](https://www.npmjs.com/package/virtua), [Vue Virtual Scroller](https://www.npmjs.com/package/vue-virtual-scroller)입니다. 실행 코드와 원본 JSON은 `benchmarks/virtual-ecosystem`에 있습니다.

```sh
pnpm --filter @sectile/benchmark-virtual-ecosystem dev
```

pnpm --filter @sectile/virtual benchmark
