# 가상화 벤치마크

같은 10만 개 행을 일곱 개 라이브러리로 그렸습니다. 처음 표시하는 시간과 스크롤 반응, 실제로 만든 DOM 수를 재고, 삽입·이동·삭제·높이 변경 뒤 화면이 얼마나 빨리 안정되는지도 따로 확인했습니다.

## 동적 높이 실험

모든 행은 48px 예상값으로 시작합니다. 높이 변경 실험에서는 화면에 보이는 행 하나를 96px로 바꿉니다. 정확한 높이는 브라우저 DOM에서 읽고, 가상화 API에는 처음의 48px 예상값만 제공합니다.

각 라이브러리가 요구하는 연결 방식은 그대로 따랐습니다. `react-virtualized`는 측정 캐시를 비우고 목록 배치를 다시 계산하라는 호출이 필요합니다. 나머지 비교 대상은 DOM 크기 변경을 자동으로 감지하는 API를 사용했습니다. 이런 앱 코드의 차이도 실행 시간에 포함됩니다.

## 목록 변경 실험

삽입·이동·삭제·높이 변경을 목록의 세 지점에서 실행합니다.

- 시작: 첫 번째 행
- 중간: 50,000번째 행을 화면 맨 위에 둔 상태
- 끝: 마지막 행이 보이도록 맨 아래까지 내린 상태

삽입과 삭제, 높이 변경은 해당 지점의 행 하나를 바꿉니다. 이동은 그 행과 바로 옆 행의 순서를 맞바꿉니다. 매번 10만 개의 원본 목록으로 되돌린 뒤 같은 실험을 10회 반복합니다.

시간은 목록 변경을 요청한 순간부터 DOM 순서와 행 높이, 전체 스크롤 높이, 기준 행의 위치가 모두 맞는 첫 프레임까지 잽니다. 중간에 화면이 깨졌다가 복구된 경우에는 안정화 시간과 실패 기록을 함께 남깁니다.

## 실패 판정

다음 현상을 프레임마다 검사합니다.

- 행 ID의 누락·중복·잘못된 순서
- 예상 높이와 다른 행
- 행 사이의 빈틈과 겹침
- 화면 위아래에 생긴 빈 영역
- 전체 스크롤 높이 오차
- 목록 변경과 관계없이 움직인 기준 행

한 프레임이라도 어긋나면 실패입니다. 같은 잘못된 상태가 3프레임 연속 이어지면 정상 상태에 도달하지 못한 것으로 기록합니다. Sectile에서 발생한 실패는 원본 결과에서 `fatal`로 구분합니다.

## 고정 높이 비교 조건

고정 높이 비교는 720 × 480px 화면에 높이 48px인 행 10만 개를 그립니다. 문구와 CSS, 표시할 데이터는 모두 같습니다. 라이브러리마다 8행 분량의 여유 구간을 요청했습니다.

라이브러리 순서를 바꿔 가며 다섯 번 실행했습니다. 매 실행에서 처음 다섯 번의 스크롤을 준비 과정으로 빼고, 다음 40번을 기록했습니다. 스크롤 시간은 `scrollTop`을 바꾼 순간부터 목표 행이 DOM에 나타날 때까지입니다.

`만든 행`은 화면과 여유 구간에 실제로 만든 행 수입니다. `생성된 DOM 요소`에는 라이브러리가 추가한 래퍼도 들어갑니다. 같은 HTML 행을 보여 주는 데 필요한 내부 DOM까지 각 라이브러리의 실행 비용으로 계산했습니다.

2026년 8월 27일, Chrome 151, Apple Silicon, macOS에서 측정했습니다. 절대 시간은 기기와 브라우저 상태에 따라 달라집니다. 라이브러리 사이의 상대 차이와 실패 여부를 함께 읽어야 합니다.

비교 대상은 [TanStack Virtual](https://www.npmjs.com/package/%40tanstack/react-virtual), [react-window](https://www.npmjs.com/package/react-window), [React Virtuoso](https://www.npmjs.com/package/react-virtuoso), [react-virtualized](https://www.npmjs.com/package/react-virtualized), [Virtua](https://www.npmjs.com/package/virtua), [Vue Virtual Scroller](https://www.npmjs.com/package/vue-virtual-scroller)입니다. 실행 코드와 원본 JSON은 `benchmarks/virtual-ecosystem`에 있습니다.

```sh
pnpm --filter @sectile/benchmark-virtual-ecosystem dev
```

## Sectile 배치 계산

브라우저 비교에는 프레임워크와 DOM 작업이 모두 들어갑니다. 아래 명령은 그 비용을 빼고 `@sectile/virtual`의 크기 색인과 화면 범위 조회, 배치 결과 생성만 측정합니다.

```sh
pnpm --filter @sectile/virtual benchmark
```
