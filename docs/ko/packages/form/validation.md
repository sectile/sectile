# 검증과 오류

Form은 서로 다른 검증 출처를 억지로 같은 것으로 취급하지 않으면서 하나의 정렬된 오류 모델로 모읍니다.

## 규칙을 소유하는 출처 선택

| 출처 | 용도 |
| --- | --- |
| 브라우저 기본 제약 | `required`, 입력 type, 길이 등 HTML 제약 |
| 필드·애플리케이션 검증 | 로컬에서 확인할 수 있는 제품 규칙 |
| Standard Schema | 최종 입력 검증과 출력 변환 |
| 서버 오류 | 저장 요청 뒤에만 알 수 있는 거절 |

네트워크 장애 같은 제출 실패는 잘못된 필드가 아닙니다. Form은 이를 submission 상태에 둡니다. 서버가 특정 값을 거절했을 때만 필드와 연결된 server issue를 반환하세요.

## 오류 식별과 포커스

하나의 오류는 주 필드 하나와 여러 관련 필드를 가리킬 수 있습니다. 요약에는 한 번만 나타나고 관련된 모든 필드는 invalid가 됩니다. 제출이 실패하면 host는 validator 반환 순서가 아니라 실제 화면에서 가장 앞선 잘못된 필드에 포커스를 옮깁니다.

필드 값이 바뀌면 그 값과 관련된 서버 오류만 지워지고, 관련 없는 입력은 영향을 주지 않습니다. `validateOn`과 `revalidateOn`은 상호작용 중 검사 시점을 정하며 제출할 때는 항상 전체 검증을 실행합니다.

템플릿 코드와 메시지 구성은 [Vue 검증과 오류](./vue/validation), 기존 HTML 폼의 설정은 [DOM 폼](./dom/)과 [DOM API](./dom/api)에서 확인하세요.
